## 03 — Selected work

### 🌧️ Vrishti AI — rainfall intelligence

An ML pipeline built around **INSAT-3DR satellite observations** to study and predict rainfall across India.

**Why it matters:** this is the kind of project where the interesting work isn't the model alone. It is the chain around it — cleaning noisy satellite observations, aggregating temporal data, selecting meaningful atmospheric features, validating without leakage, and exposing the result through a usable interface.

`Python` `scikit-learn` `LightGBM` `FastAPI` `React` `geospatial data`

→ [Repository](https://github.com/IshanG2111/RainFall-Prediction-Model-)

---

### 🌱 EcoQuest — an ecological operating system

A deliberately unusual sustainability platform that treats learning as an **interactive world rather than a sequence of pages**.

It combines gamification, a force-directed ecological knowledge graph, simulations, dashboards, authentication, progression, and AI-assisted knowledge linking. The project is also where I pushed hardest on the relationship between **engineering and visual design**.

`Next.js` `TypeScript` `Firebase` `MongoDB` `Gemini` `D3.js` `React Three Fiber`

→ [Repository](https://github.com/IshanG2111/EcoQuest) · [Live experience](https://ecoquest-woad.vercel.app/desktop)

---

### 🧠 LeetCode → Knowledge Engine

An automated developer workflow that turns coding activity into structured knowledge.

The pipeline syncs LeetCode submissions, handles historical data, deduplicates records, and uses AI to enrich the resulting knowledge base. The goal isn't another stats dashboard — it is **turning activity into something reusable for learning**.

`n8n` `Node.js` `Gemini` `Notion` `ETL` `automation`

→ [Repository](https://github.com/IshanG2111/LC-automation)

---

### ✋ Gesture-based document interfaces

Computer-vision experiments that replace conventional input with **hand gestures** — including an AR-style document viewer and gesture-based media controls.

The interesting constraint: the interaction has to feel immediate. That means lightweight landmark detection, gesture classification, state handling, and feedback loops rather than simply detecting a hand on screen.

`Python` `OpenCV` `MediaPipe` `computer vision`

→ [AR Viewer](https://github.com/IshanG2111/ar-notes-opener) · [Media Controls](https://github.com/IshanG2111/Gesture-Based-Media-Controls)

---

### 🏭 Enterprise engineering

During my internships at **Tata Cummins** and **Tata Motors**, I worked on software used in real organizational workflows — from document digitization to supplier relationship management.

That experience changed how I think about engineering: a feature is not finished when the UI works. It has to survive **real users, real data, permissions, deployment constraints, and operational reality**.

## 05 — How I approach a problem

```text
             ┌──────────────────┐
             │     PROBLEM      │
             └────────┬─────────┘
                      ↓
             ┌──────────────────┐
             │  understand the  │
             │  actual constraint│
             └────────┬─────────┘
                      ↓
             ┌──────────────────┐
             │      MODEL       │
             │ data / state / UX│
             └────────┬─────────┘
                      ↓
             ┌──────────────────┐
             │      BUILD       │
             │ small → testable │
             └────────┬─────────┘
                      ↓
             ┌──────────────────┐
             │     MEASURE      │
             │ latency / quality│
             └────────┬─────────┘
                      ↓
             ┌──────────────────┐
             │    AUTOMATE      │
             │ remove repetition│
             └────────┬─────────┘
                      ↓
                  ship → learn
```

I tend to optimize for **clarity before cleverness**. If a system can be made simpler without losing capability, I usually want the simpler system.
